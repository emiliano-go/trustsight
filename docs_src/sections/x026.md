<!-- name: Unresolved Constructs In Executable Positions -->

**MEDIUM** (weight 15; HIGH at three or more distinct names) · category `evasion`

Fires when an assignment the tokenizer refused reaches an *executable position*
in `build()`, `prepare()`, `check()` or `package()`: a command word, an
interpreter/source/eval target, a pipeline into a shell, or an `xargs`/`find
-exec` target. Using the value as a filename, URL, job count, or test operand is
data flow, not execution. Top-level metadata (`pkgver=$(date)`, decorative
variables) is not an executable position either. Function-local declarations
are excluded from W008's report-facing boundary list.
The finding lists the unresolved names and the functions that execute
them; `[thresholds] x026.min_count` sets the firing floor (default 1).
The unresolved-is-not-seen contract holds: X026 reports the refusal, it
never makes another rule treat the value as read.

An unresolved construct is *also* an analysis boundary: [W008](unverifiable.md#w008)
names what the analysis could not read (weight 0), while X026 scores the
suspicion. Both may fire; they are different claims about the same line.

Measured on the locked benign corpus: 130 on the v1 corpus (3.5%, 27 packages) - the
honest-refusal floor (`CONFIGURE_FLAGS=$(...)`, `VERSION=$(date)`,
Windows-ISO helper variables).
